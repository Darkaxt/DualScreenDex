# DualDex 1.1.0-rc.60

RC60 continues source-backed Gen III compatibility with fail-closed embedded teachable and egg acquisitions for headerless unified species records.

## Embedded Gen III move acquisitions

- Complete compiled Thumb getters prove species bounds, 260-byte indexing, active-row checks, row-zero null fallback, relative pointer fields, and normal return before lists are accepted.
- Teachable and egg pointers are independently gated and require bounded u16 lists ending in `0xFFFF`.
- Teachable lists use the existing machine-acquisition contract while retaining their documented combined machine/tutor provenance.
- The independently resolved tutor module remains active; a failed embedded field disables only that field.
- Referenced move closure preserves valid compiled IDs even when a move name is not independently decoded, leaving unsupported fields explicitly unavailable.

## Source-backed compatibility

- Dreamstone improves from 20/24 at 83.31% to 22/24 at 91.64%.
- Its catalog materializes 47,108 teachable links and 4,321 egg links while retaining 4,247 generic tutor links.
- An independent Crippling control materializes 88,104 teachable and 4,671 egg links from different roots and compiler-bound getter forms.
- Corrupting a teachable or egg pointer disables only that acquisition module; the sibling field, tutor, abilities, routing, and startup remain accepted.
- The other seven characterized Gen III controls retain their routing, feature counts, compatibility scores, and prior materialized counts.

## Validation and delivery

- Focused Dreamstone, Crippling, and malformed-pointer controls pass.
- The one-job eight-ROM matrix completed with zero parser, persistence, or decoded cross-reference errors; all six selected catalogs persisted and reopened.
- Parser schema 40 intentionally rebuilds cached catalogs once so newly supported acquisitions are materialized.
- RC60 is an in-place prerelease update of `com.darkaxt.dualdex` with version code `1010060`.
- Production signing and APK publication remain isolated to the protected GitHub release workflow.
- The APK is not installed or launched as part of release publication.

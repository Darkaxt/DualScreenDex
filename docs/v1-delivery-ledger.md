### Stage 2 persistent ROM catalog

- Database contract: parser schema 1 uses one metadata row plus ten required `gzip+json` sections for species, moves, types, abilities, the type chart, encounters, capture balls, learnset rulesets, capabilities, and diagnostics. A catalog is reopenable only after a single transaction marks all required sections complete.
- Identity contract: the database filename and authoritative join key are the full ROM SHA-256. CRC32, byte size, internal title, family, platform, source kind, and selected ZIP entry are retained only as lookup and verification evidence; basenames never authorize a cache match.
- Recovery checks: incomplete transactions are not published, incompatible parser-schema catalogs are invalidated, corrupt private cache files are rejected, and direct and ZIP sources containing identical ROM bytes resolve to one database.
- Android native SQLite: official Emerald produced `a9dec84dfe7f62ab2220bafaef7479da0929d066ece16a6885f6226db19085af.sqlite` at 569,344 bytes with CRC32 `1F1C08FB`, direct-source metadata, all ten sections, and `PRAGMA integrity_check = ok`. Modern Emerald produced its independent SHA database at 663,552 bytes with ZIP-entry provenance.
- Cold versus reopen: Modern Emerald completed a cold ZIP parse and persistence in 101,783 ms; process-start cache reopen completed in 3,677 ms without ROM/provider access (about 27.7 times faster). Official Emerald completed its direct-file parse and persistence in 109,288 ms after selection; the preceding file-picker wait is excluded from parser time.
- Progressive presentation: committed parser work publishes 0/20/40/60/80/100 percent and renders `Loading... (N%)`; the value is derived only from committed work units. Finer `EXTENDED` sub-progress remains a Stage 7 tuning candidate only if real parser sub-units are introduced.
- Corpus: all 14 in-scope named ROMs selected, wrote, closed, reopened, and decoded equal to their source catalog. This includes 11 exact official games and Modern Emerald, Sword and Shield Ultimate Plus, and Unbound as structural derivatives; spin-offs and Mystery Dungeon remain excluded. All 14 SQLite files passed `PRAGMA integrity_check` and the report contains no decoded text, sprites, ROM bytes, or save data.
- Regression: 171 JVM/Android unit tests passed with zero failures or skips; all 95 requested Gradle tasks completed; 12 browser files and 28 tests passed; the production TypeScript/Vite build passed; and both dedicated-AVD instrumentation tests passed, including the native Android SQLite transaction path.

### Stage 6 production settings and isolated Memory Mapper Lab

- Settings: the complete companion document now persists information policy, ruleset, battle-tab visibility, font scale, density, contrast, theme, Docked/Overlay mode, and Auto/Handheld/External display targeting. `Auto` preserves the launcher-selected display; explicit targets use Android display launch options with a failed-request loop guard. Existing SAF grants, RetroArch verification, save associations, and save-backed knowledge retain their independent established stores.
- Scoped maintenance: `CLEAR INACTIVE CATALOGS` accepts only SHA-named SQLite files inside the catalog namespace, preserves the active catalog and unrelated files, and makes no seen/caught reset claim. Mapper clearing accepts only mapper session/temp names inside `filesDir/memory-mapper`.
- Read-only protocol: the mapper API can represent only `MemoryRead`; no write request or write method exists. Current RetroArch grammar is `READ_CORE_MEMORY <hex-address> <decimal-byte-count>`, and 512-byte requests remain below the 4,096-byte UDP packet boundary. Lack of a reply leaves a heartbeat capture pending rather than imposing a cancellation timeout.
- Capture/export: the lab starts disabled on every process, uses one enable confirmation, labels seven predefined battle/overworld events plus custom events, stores immutable region hashes and raw bytes in its private namespace, and computes capped contiguous before/after ranges. Android export goes through the system document picker; browser development mode downloads the same self-contained JSON with Base64 regions and diff bytes.
- Isolation: parser, catalog, save, companion-core, RetroArch-session, and production runtime sources are structurally forbidden from importing mapper models. Disabled/failure/disable tests trace zero writes and preserve a sibling production-database SHA-256; an on-device fake transport captured/exported one session while the catalog marker remained byte-identical.
- UI/device: packaged Settings and mapper pages were inspected through the dedicated AVD WebView with Modern Emerald restored from its SHA cache. Both scroll regions fit their Android surface without clipping; Game and Dark palettes remained readable. Temporary screenshots and the temporary automated-launch ROM copy were removed rather than committed.
- Verification: 273 JVM/Android unit tests passed with zero failures, errors, or skips; 14 browser test files and 41 tests passed; the production TypeScript/Vite build and Android lint passed; and all three instrumentation tests passed explicitly on `emulator-5556`. The final local debug APK is 14,315,385 bytes with SHA-256 `60F5492CC951820C853E01FA7C87FEDE659EB5FED5A01AC61F39B56F361B2E6F`; it was installed only on `emulator-5556`. `emulator-5554` was not addressed by any Stage 6 install or instrumentation command.

# DualScreenDex 1.1 player-state verification

## Scope

This gate verifies the approved 1.1 read-only player-state plan through the production catalog,
SQLite cache, runtime projection, web API, and Android display-continuity policy. It does not send
game input, publish raw memory addresses, or expose unobserved opponent moves.

Implementation lineage:

- normalized player models and codecs: `676f648`, `3339999`, `674c5f8`;
- typed player runtime layouts and ROM-derived assets: `538b562`, `abaf233`;
- one live read snapshot and live-over-save authority: `9b36334`, `4312376`;
- Trainer Card and Party API/UI: `292b865`, `08a5d0f`;
- display selection and lifecycle recovery: `4a49009`, `94ab11f`.

It proves Trainer name/gender/ID, money, playtime, badges, seen/caught counts, the selected avatar,

## Display continuity

The pure policy and `MainActivity` lifecycle adapter verify:

- one listener registered while started and removed while stopped;
- `AUTO` never relocates the activity;
- `HANDHELD` chooses only the unique default display;
- `EXTERNAL` chooses only one unambiguous eligible external display;
- target changes, display removal and resume all pass through the same policy;
- a failed relaunch does not loop against the same display; and
- a successful move preserves the current same-origin companion route without creating a second
  WebView, `Presentation`, service, timeout, or manifest component.

## Verification commands

The release gate runs the exact real controls together, then the complete affected Gradle modules,
web unit suite, and production web build. ROM paths and raw/save bytes are intentionally absent from
this report and from the application projection.

## Related-project review

`Goldoire/pokeemerald-dualscreen` was re-reviewed from `d27ecd5` through upstream `8ec6cba`. The
passive double-battle ownership state and richer normalized party artwork are useful follow-ups. Its
touch battle takeover, synthetic inputs, direct foe-weakness feed, widescreen renderer, and asset-hole
packaging are not appropriate for this read-only multi-ROM release. The detailed decision is recorded
in `docs/reports/2026-08-15-pokeemerald-dualscreen-reference.md`.
